# cmtz-add-superposition

Additive superposition gate (v4).

The datapath is generated by the Verilog backend of the Cook-Mertz compiler from `04_add_superposition.cmtz`:

```
-- 04_add_superposition.cmtz
--
-- Additive superposition gate (v4).
-- add(a, b) computes (a + b) mod p — the result lands on some element
-- of F_p, which is itself a root of unity since F_p* is cyclic.
--
-- Math (F_17, g=3):
--   embed_0 = ω^0 = 1
--   embed_1 = ω^4 = 13
--   superposed = (1 + 13) mod 17 = 14 = ω^9
--
-- After rotation by ω^3 = 10:
--   rot_superposed_rotated = 14 · 10 mod 17 = 140 mod 17 = 4 = ω^12
--
-- Key insight: unlike rotate (which stays on the root-of-unity torus),
-- add can produce values that are NOT consecutive powers of g; here
-- j=0 + j=4 → j=9, a non-trivial "jump" in exponent space.

field(17, 19);
roots(17) as omega17;

embed(0, 0);            -- embed_0 = ω^0 = 1
embed(1, 4);            -- embed_1 = ω^4 = 13

-- Superpose: (1 + 13) mod 17 = 14 = ω^9
add(embed_0, embed_1) as superposed;

-- Rotate the superposition by ω^3 = 10:
-- 14 · 10 = 140 ≡ 4 mod 17 = ω^12
rotate(superposed, rotated, 3);

measure(embed_0,               mod_p) as phi0;         -- expect  1
measure(embed_1,               mod_p) as phi4;         -- expect 13
measure(superposed,            mod_p) as sum14;        -- expect 14
measure(rot_superposed_rotated, mod_p) as sum_rotated;  -- expect  4
```

The program's literal embeds are replaced by input ports, so the datapath computes the same graph for any values in 0 to 16 instead of the constants in the source. It has 2 pipeline stages, one result per clock, and no `%` operators: reductions are unrolled conditional subtracts.

## Ports

| Port | Bits | Carried as |
|---|---|---|
| `in_embed_0` | 5 | request byte 0 |
| `in_embed_1` | 5 | request byte 1 |
| `out_phi0` | 5 | reply byte 0 |
| `out_phi4` | 5 | reply byte 1 |
| `out_sum14` | 5 | reply byte 2 |
| `out_sum_rotated` | 5 | reply byte 3 |

## UART protocol

115200 8N1 on the on-board USB bridge. Send 2 bytes (each 0 to 16), read 4 bytes back. A complex port is two bytes, real part first. If any request byte is 17 or more, every reply byte is `0xFF`. If a request stalls partway for 250 ms, the bytes received so far are dropped. Bytes sent while a reply is going out are ignored, so read the whole reply before sending the next request.

Example: `00 03` replies `00 03 03 0D`.

LEDs (active low): `leds[4:0]` show the low bits of the first reply byte, `leds[5]` lights after an error reply.

## Files

| File | What |
|---|---|
| `cmtz_add_superposition_uart.v` | Top module `cmtz_add_superposition_uart`: UART receiver and transmitter and a control state machine around the datapath. Generated. |
| `cmtz_add_superposition.v` | The datapath. Generated. |
| `cmtz_add_superposition_tb.v` | Datapath testbench with 289 vectors, expected values from the compiler's Python reference. Generated. |
| `cmtz_add_superposition_uart_tb.v` | Whole-design testbench: bit-bangs the UART protocol for every vector, then checks the out-of-range reply and the resync timeout. Generated. |
| `pins.cst` | `clk` pin 4, `tx` pin 69, `rx` pin 70, LEDs pins 15 to 20 |
| `apio.ini` | Board and top module |

Regenerate with `examples/fpga/build_projects.py` in the Cook-Mertz repo rather than editing the generated files.

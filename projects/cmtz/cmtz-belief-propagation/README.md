# cmtz-belief-propagation

Real-valued discrete circular belief propagation: one Fourier bin,

The datapath is generated by the Verilog backend of the Cook-Mertz compiler from `13_belief_propagation.cmtz`:

```
-- 13_belief_propagation.cmtz
--
-- Real-valued discrete circular belief propagation: one Fourier bin,
-- one full sweep over a 3-node chain X0 - X1 - X2.
-- See 13_belief_propagation_runner.py for the full derivation.
--
-- X0 and X2 are leaf variables injecting local evidence at a single
-- frequency bin k (F_p stands in for one Fourier coefficient). Each edge
-- carries a fixed (compile-time) factor coefficient phi_k. Since F_p* is
-- cyclic, any such coefficient equals omega^j for some j, so the
-- factor-to-variable scaling step is expressed with rotate() (multiply by
-- a compile-time root exponent) rather than a general polynomial.
--
-- X1's belief is the *product* of its two incoming messages — the
-- variable-to-factor step of belief propagation. That product is between
-- two registers computed at runtime, which is exactly the gap v4 could
-- not express (IRRotate/IRPoly only multiply a register by a compile-time
-- constant; IRAdd only adds). mul() — v5 — is what makes this line
-- possible.

field(7);
roots(7) as omega7;                 -- (1, 3, 2, 6, 4, 5)

embed(0, 1);                        -- X0 evidence at bin k: omega^1 = 3
embed(1, 2);                        -- X2 evidence at bin k: omega^2 = 2

-- factor(X0,X1) coefficient phi_k = 2 = omega^2 -> rotate by j=2
-- msg_X0_to_X1 = 3 * 2 = 6
rotate(embed_0, msg01, 2);

-- factor(X1,X2) coefficient phi_k = 3 = omega^1 -> rotate by j=1
-- msg_X2_to_X1 = 2 * 3 = 6
rotate(embed_1, msg21, 1);

-- Variable-to-factor step at X1: product of incoming messages.
-- belief_X1 = 6 * 6 = 36 mod 7 = 1
mul(rot_embed_0_msg01, rot_embed_1_msg21) as belief_X1;

measure(belief_X1, mod_p) as result;
```

The program's literal embeds are replaced by input ports, so the datapath computes the same graph for any values in 0 to 6 instead of the constants in the source. It has 2 pipeline stages, one result per clock, and no `%` operators: reductions are unrolled conditional subtracts.

## Ports

| Port | Bits | Carried as |
|---|---|---|
| `in_embed_0` | 3 | request byte 0 |
| `in_embed_1` | 3 | request byte 1 |
| `out_result` | 3 | reply byte 0 |

## UART protocol

115200 8N1 on the on-board USB bridge. Send 2 bytes (each 0 to 6), read 1 byte back. A complex port is two bytes, real part first. If any request byte is 7 or more, every reply byte is `0xFF`. If a request stalls partway for 250 ms, the bytes received so far are dropped. Bytes sent while a reply is going out are ignored, so read the whole reply before sending the next request.

Example: `00 03` replies `00`.

LEDs (active low): `leds[4:0]` show the low bits of the first reply byte, `leds[5]` lights after an error reply.

## Files

| File | What |
|---|---|
| `cmtz_belief_propagation_uart.v` | Top module `cmtz_belief_propagation_uart`: UART receiver and transmitter and a control state machine around the datapath. Generated. |
| `cmtz_belief_propagation.v` | The datapath. Generated. |
| `cmtz_belief_propagation_tb.v` | Datapath testbench with 49 vectors, expected values from the compiler's Python reference. Generated. |
| `cmtz_belief_propagation_uart_tb.v` | Whole-design testbench: bit-bangs the UART protocol for every vector, then checks the out-of-range reply and the resync timeout. Generated. |
| `pins.cst` | `clk` pin 4, `tx` pin 69, `rx` pin 70, LEDs pins 15 to 20 |
| `apio.ini` | Board and top module |

Regenerate with `examples/fpga/build_projects.py` in the Cook-Mertz repo rather than editing the generated files.

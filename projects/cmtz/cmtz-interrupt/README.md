# cmtz-interrupt

Strict catalytic region: interrupt { body } restoring (regs)

The datapath is generated by the Verilog backend of the Cook-Mertz compiler from `05_interrupt.cmtz`:

```
-- 05_interrupt.cmtz
--
-- Strict catalytic region: interrupt { body } restoring (regs)
--
-- Contrast with catalytic { } restoring () from 03_conjugate_catalytic.cmtz:
--
--   catalytic { }  → lowers to IRRegion  (ADVISORY — no enforcement)
--                     Used for main-process workspace management.
--                     The compiler trusts the programmer's restoration claim.
--
--   interrupt { }  → lowers to IRCatalyticRegion  (STRICT — verified)
--                     Used for interrupt handlers that borrow running registers.
--                     The verifier checks that listed registers are not clobbered
--                     by any node inside the body (§2.7 invariant).
--
-- This example protects embed_1 (= ω^6 = 15) across an interrupt that
-- computes a rotation in its own temporary registers.  embed_1 is never
-- touched inside the body, so the strict check passes.
--
-- Field: F_17  (m = p-1 = 16, g = 3)
--   ω^0 = 1    ω^3 = 10    ω^6 = 15    ω^8 = 16

field(17, 19);
roots(17) as omega17;

-- Main workspace
embed(0, 0);        -- embed_0 = ω^0 = 1  (freely modifiable)
embed(1, 6);        -- embed_1 = ω^6 = 15 (guard — must survive the handler)

-- Interrupt handler: borrows context to compute a temporary result.
-- Operates only on embed_2 and its rotation; never touches embed_1.
interrupt {
    embed(2, 3);                           -- temp = ω^3 = 10
    rotate(embed_2, embed_2, 5);           -- rot_embed_2_embed_2 = ω^8 = 16
} restoring (embed_1);

-- embed_1 must be unchanged: strict verifier enforces this.
measure(embed_1,               mod_p) as guard_val;   -- expect 15
measure(embed_0,               mod_p) as workspace;   -- expect  1
measure(rot_embed_2_embed_2,   mod_p) as handler_out; -- expect 16
```

The program's literal embeds are replaced by input ports, so the datapath computes the same graph for any values in 0 to 16 instead of the constants in the source. It has 1 pipeline stage, one result per clock, and no `%` operators: reductions are unrolled conditional subtracts.

## Ports

| Port | Bits | Carried as |
|---|---|---|
| `in_embed_0` | 5 | request byte 0 |
| `in_embed_1` | 5 | request byte 1 |
| `in_embed_2` | 5 | request byte 2 |
| `out_guard_val` | 5 | reply byte 0 |
| `out_workspace` | 5 | reply byte 1 |
| `out_handler_out` | 5 | reply byte 2 |

## UART protocol

115200 8N1 on the on-board USB bridge. Send 3 bytes (each 0 to 16), read 3 bytes back. A complex port is two bytes, real part first. If any request byte is 17 or more, every reply byte is `0xFF`. If a request stalls partway for 250 ms, the bytes received so far are dropped. Bytes sent while a reply is going out are ignored, so read the whole reply before sending the next request.

Example: `08 10 0F` replies `10 08 07`.

LEDs (active low): `leds[4:0]` show the low bits of the first reply byte, `leds[5]` lights after an error reply.

## Files

| File | What |
|---|---|
| `cmtz_interrupt_uart.v` | Top module `cmtz_interrupt_uart`: UART receiver and transmitter and a control state machine around the datapath. Generated. |
| `cmtz_interrupt.v` | The datapath. Generated. |
| `cmtz_interrupt_tb.v` | Datapath testbench with 66 vectors, expected values from the compiler's Python reference. Generated. |
| `cmtz_interrupt_uart_tb.v` | Whole-design testbench: bit-bangs the UART protocol for every vector, then checks the out-of-range reply and the resync timeout. Generated. |
| `pins.cst` | `clk` pin 4, `tx` pin 69, `rx` pin 70, LEDs pins 15 to 20 |
| `apio.ini` | Board and top module |

Regenerate with `examples/fpga/build_projects.py` in the Cook-Mertz repo rather than editing the generated files.
